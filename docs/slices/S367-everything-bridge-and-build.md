# S367 — Everything bridge and build pipeline

## Status
Implementation in progress. S367 is not complete and no Everything app is installable yet.

## Goal and dependencies
Prove an independent, customer-owned bridge and reproducible build for selected Everything apps, beginning with Tasks. S279 and S341 are present; S382's craft serving and DNS validation is still unfinished. ADR-053 constrains the new architecture; implementation details must meet its security and recovery requirements. Do not ship the pilot without its own complete build, serve and reachability proof.

## Work in progress
`third_party/everything/` contains the pinned Tasks source and its SHA-256. The experimental `scripts/everything/prepare_tasks.py` verifies the archive, requires a caller-supplied local bridge, and replaces the remote SDK tag and upstream service worker. The replacement worker caches only its static shell and listed assets, bypassing bridge data; `scripts/everything/test_tasks_sw.cjs` simulates its fetch and cache handling. A prepared source build succeeded with an intentionally nonfunctional bridge stub and no SDK host in the resulting index or service worker. A standalone SQLite store prototype now isolates records by app and verified-subject scope, supports bounded values and atomic batches, and has restart, concurrent access and SQLite snapshot tests. A prototype request handler requires an injected identity verifier, exact allowed origin and CSRF check; its tests use a fake verifier. This is not a running app or a security acceptance test: no real authentication implementation, JS bridge, sharing, total storage quota, CSP, real-browser service-worker validation, Docker image, or integrated backup/restore exists yet. The upstream suite still uses its own mock.

### Bridge, SDK shim and behavioural gate (added 2026-11-02)
New code: `scripts/everything/puter-bridge.js` (the `puter` global, same-origin POST to `./_homestead/data`), `internal/everything/{server,devauth}.go` and `cmd/everything-bridge` (standalone server: SQLite store plus handler; handler gained `whoami` and atomic `putbatch`), and `scripts/everything/gate/` (`run_gate.sh`, harness, replacement `mock-puter.js`, `bridge-gate.test.js`).

Identity (updated 2026-11-02 after the owner decisions in the ADR-053 amendment): the production build verifies people with OIDC against Authentik (`internal/everything/oidc.go`, `sessions.go`): authorization-code flow with PKCE, state bound to the browser and single use, nonce, RS256/ES256 ID-token signature via JWKS plus `iss`, `aud`, `exp`, `nonce` checks; subject is the `sub` claim; server-side sessions (hashed id in the bridge SQLite file, HttpOnly Secure SameSite=Lax cookie scoped to the app path, idle 12h and absolute 7d expiry, logout deletes). `index.html` is served by the bridge with `<meta name="homestead-csrf">` injected per session and an unauthenticated load redirects to sign-in; every data mutation and logout needs the token and the exact Origin. Configuration (flags or `HOMESTEAD_EVERYTHING_*`): issuer, client id, `-oidc-client-secret-file` (file only), redirect URL, one `-origin`, `-base-path`, `-static-dir`, optional `-ca-file`; the production build refuses to start if any is missing or unsafe. The development verifier (`devauth.go`) remains behind `-tags everythingdev` for the gate and is not authentication. `prepare_tasks.py` now hides Tasks' Share button and calendar-feed setting by an exact-match patch of the pinned source (the build fails if the target changes); the local Download .ics button stays.

Gate results (`scripts/everything/gate/run_gate.sh <empty dir> suite|bridge`, Node 24, pinned source, `npm ci --ignore-scripts`; real Go bridge process with temp SQLite and the dev identity; no upstream mock):
- `bridge` mode, Tasks' real `Store` through the shim: 7/7 pass (3 runs, 2026-11-02): persistence across bridge restart; two concurrent clients converge (last-write-wins per key, healed by Tasks' record merge after re-reads); person B cannot read A's KV or files and a client-supplied subject is ignored; sharing, collaboration and signed URLs refused (`bridge_unsupported`); missing, forged, revoked, expired session, wrong CSRF and foreign Origin refused; oversize values refused and a duplicate-key batch rolls back.
- Limitation (root cause of the earlier "two concurrent clients" failure, 2026-11-02): when two devices boot at the same moment on an empty account, each Tasks Store mints its own dataset epoch and seeds its own default list; the later-minted epoch replaces the other wholesale (upstream `src/lib/store.js` `#mergeCloud`), so the other device's early edits are lost. This is upstream behaviour on real Puter KV too (whole-key last-write-wins). The gate test now boots the second device after the first has synced, and a second test pins the simultaneous-boot convergence. Gate: bridge mode 7/7, three runs.
- `suite` mode, the 12 upstream test files with `tests/helpers/mock-puter.js` replaced by a bridge-backed helper (kvMap/fileMap are write-through mirrors; each reset uses a fresh bridge subject): 172 of 235 pass. The 63 failures are all sharing: 27 collab, 23 kvshare (the other 1 passes), 13 store (snapshot share links, ICS feed, wipe and import of share files) fail because `fs.getReadURL` is refused or the KV-share surface is absent; 2 of the kvshare failures are on the missing `perms`. None fail for storage, merge, offline or isolation reasons.  The pure-logic files (dates, ics, quick actions, parser, recurrence, reminders, share viewer) pass in full, as do offline 8/8 and sync 19/19; store passes 39/52.
- Limits: helper mirrors are not the real shared account semantics for cross-account tests; shares are not supported at all, so those upstream tests cannot pass. This is the chosen handling of sharing under ADR-053 (refuse), not a pass. `enableShare` writes its private snapshot file before the URL is refused; the file stays inside the person's own scope.

### Service worker and CSRF token (added 2026-11-02)
The replacement Tasks worker (`scripts/everything/tasks-sw.template.js`) no longer precaches or serves `./` or `index.html`: navigations are network-only and, when the network fails, get a fixed 503 page with no token and no user data. Nothing under `_homestead/` (data, session, login, callback, logout, the shim) is precached, intercepted or stored; only named, query-less static assets are cache-first, and only 200 same-origin non-redirected responses are put in the cache. Consequence: the app shell cannot load offline; an already-open page keeps working and Tasks' offline queue is unchanged (the shim still rejects `network_error` when the bridge is unreachable). Bridge: `index.html`, the signed-out redirect and all `_homestead/*` responses are `Cache-Control: no-store`; unregistered `_homestead/` paths 404 (the file server cannot serve them; only `puter-bridge.js` is served, `no-cache`); `/assets/<name>-<hash>.<ext>` is `public, max-age=31536000, immutable`; other files `no-cache`. New `GET _homestead/session` (session required, `no-store`, same-site only, no CORS) returns `{csrf, subject}`; the shim, on a 401/403 from a mutation, fetches it with `cache: 'no-store'`, retries once, and on 401 sends the person to sign-in (not for `whoami`). A wrong token on the wire is still 403; only a valid session can obtain a token. Tests: Go (`TestOIDCSessionEndpoint`, `TestOIDCCacheHeaders`), `test_tasks_sw.cjs`, gate test updated (shim heals a stale token; raw wrong token 403; revoked session `auth_required`), and the optional real-browser check `scripts/everything/gate/run_browser_check.sh <empty dir>` (builds the prepared app, serves it from the dev bridge under `/apps/tasks`, drives headless Chrome over the DevTools protocol: no index/bridge path/token in Cache Storage, offline write rejects `network_error`, offline reload shows the token-free page, a second person on the same browser gets their own token). The dev identity gained a static-serving mode and a GET sign-in for this check; it is not authentication.

Remaining for S367: end-to-end proof against a real Authentik (the OIDC code is tested only against a fake provider; the browser check uses the dev identity); catalog package; CSP and real-browser service-worker test. Image, Compose, quota, export, backup and daemon-independence are in the next section.

## Acceptance gate
- Resolve ADR-053, select and verify a pinned source and licence, remove the remote SDK from built assets, and build a Docker-served app reproducibly.
- Define and exercise a customer-owned per-person, per-app data and authorization boundary that operates with its Compose stack without the Homestead daemon. Authentik integration and local recovery must be documented and tested.
- Run upstream Tasks behavior against the actual bridge, not the upstream mock; cover data persistence, offline replay, concurrent clients, private isolation, sharing authorization and failed or revoked access. A pass of the unmodified upstream mock suite alone is insufficient.
- Prove explicit exposure, same-origin/CSRF controls, mounted storage, backup/restore and daemon-independent operation. Document and test unsupported optional capabilities without implying that they work.
- S368–S381 remain blocked until this gate passes. If it cannot pass, record the concrete failure and stop Track B.

### Image, Compose, quotas, export and recovery (added 2026-11-02)
Files: `images/everything/Dockerfile` (+ `Dockerfile.dockerignore`, `compose.example.yaml`, `compose.env.example`), `internal/everything/export.go`, `cmd/everything-bridge/tools.go`, `scripts/everything/gate/run_compose_check.sh`.

Image `homestead/everything-tasks:<version>`: build context is the repository root; `docker build -f images/everything/Dockerfile --build-arg SOURCE_DATE_EPOCH=1767225600 -t homestead/everything-tasks:0.0.1 .`. Stages: verify pinned archive and run `prepare_tasks.py` (python), `npm ci --ignore-scripts` plus `npm run build` (Node 24, fails if the built tree mentions `js.puter.com`), Go bridge (production tags, CGO off, `-trimpath`, `-buildid=`), then a final distroless/static image (uid 65532, no shell, file times 0, `/data` the only writable path, healthcheck is the binary's own `healthcheck` subcommand against `GET <base>/_homestead/healthz`, which is unauthenticated, no-store and returns only `ok`). Bases are digest-pinned (docs/THIRD_PARTY.md). Two `--no-cache` builds gave identical layer digests and, with `SOURCE_DATE_EPOCH`, identical image IDs (`sha256:7aa053a8...`). The image is built locally by the owner or appliance, as for craft; it is not published.

Quotas: bytes of key plus value, per person per app (default 256 MiB) and per app (default 4 GiB), configurable with `-quota-person-bytes`/`-quota-app-bytes` or `HOMESTEAD_EVERYTHING_QUOTA_*`. Checked inside `BEGIN IMMEDIATE` after the write, so a batch is all-or-nothing and racing writers (also across processes) cannot overshoot; writes that do not grow usage still succeed when over. The handler answers 413 `quota_exceeded`; the shim rejects with code `quota_exceeded`. Per-value (8 MiB) and per-batch limits are unchanged.

Export, import, backup (work on the SQLite file; the bridge may be stopped): `everything-bridge export -db F [-subject SUB] [-app APP] -out DIR` writes `manifest.json` (one object per line; compact-JSON KV values inline, others base64) and file bodies under `files/<app>/<subject-hash>/<path>`; opens the database read-only and refuses a missing file or non-empty output; it reads only the data table, so no session, login state or secret is exported. `import -db F -in DIR` loads an export (bypasses quota). `backup -db F -out NEW` takes a consistent `VACUUM INTO` snapshot (safe while running), then deletes sessions and login state from the copy.

Recovery (no daemon, no sign-in): stop the bridge; copy the backup file over `/data/bridge.db` (owner uid 65532, mode 0600) or run `import`; start it. All KV and files are restored. Sessions are deliberately not restored: everyone signs in again through Authentik. With stock tools, `sqlite3 bridge.db 'select app,subject,kind,object_key,length(value) from objects'` works on a stopped copy.

Daemon-independence proof (`scripts/everything/gate/run_compose_check.sh`, plain `docker compose`, no Homestead daemon, dead issuer URL because discovery is lazy): refusal without OIDC config; healthy container with read-only root and no host port; `healthz` 200; unauthenticated page 302; data API 401; data seeded with `import` survives `down`/`up`; export from the stopped volume; backup restored into a fresh volume re-exports the same data. Not proven here: an actual sign-in against Authentik over Compose, and a catalog package.
