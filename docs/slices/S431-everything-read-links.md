# S431: Everything read links on local names

ADR-058 section 4 (route, token, limits, headers, rate limit, logging). Depends on S425-S430. Bridge, shim, one tool command and a docker-config test; no daemon, API, CLI or dashboard change, so no PARITY change. The viewer (S432), the public exposure plan and `read_links_not_exposed` (S433) and every app UI (S437-S440) are not part of this slice.

## Scope
`fs.getReadURL(path, expiresIn)` in the shim, the `fs.getReadURL` data operation, the `read_links` table, the raw route `GET|HEAD <base>/_homestead/read/<token>`, revocation on delete/rename/tree delete/purge, the `links list|revoke` tool, and the edge client-address verification the ADR left to this slice.

## Design as built
- `internal/everything/readlinks.go` (store): `read_links(id, app, owner_subject, object_key, token_hash, created_at, expires_at, revoked_at, last_used_at, hits)`. Token = 32 random bytes, base64url (43 characters); only SHA-256 (hex) is stored. `CreateReadLink` requires the caller's own existing file (a folder is `invalid_argument`, `~shared` and bad keys are `invalid_argument`, another person's or app's path is the same `path_not_found` as a missing one), a live non-purged owner, default 7 days, minimum 1 minute (below is `invalid_argument`), clamp to the cap (365 days, lowerable with `-read-link-max-days` / `HOMESTEAD_EVERYTHING_READ_LINK_MAX_DAYS`, never raised), at most 10 live per (owner, path) and 500 per owner per app (`read_link_limit`, 429; expired and revoked links do not count). `OpenReadLink` answers one `ErrNotFound` for unknown, expired, revoked, purged-owner and vanished-file tokens and counts the hit.
- Revocation is in the same transaction as the change: `Delete`, `DeleteTree` (at or under the folder, not the sibling prefix), `Rename` (the old path) and `PurgePerson` (all of the person's links). An overwrite keeps the link (Tasks needs current content); re-creating a path never revives one. A recipient deleting through a folder share runs the same store code, so it revokes too.
- `internal/everything/readroute.go`: `fs.getReadURL` goes through the existing POST data route (Origin, Sec-Fetch-Site, content type, CSRF). Request field `ttl` (seconds, 0 = default). It replies `{url, id, expires}` where `url` is `<request Origin><base>/_homestead/read/<token>`; the Origin already matched the one configured origin. There is no switch: links are minted only when an app calls the SDK, and the sharing switch is not involved.
- The route ignores cookies and `Authorization` and sets no cookie. Headers: `Content-Type` from a fixed extension allowlist (json, txt, ics, md, csv, png, jpg, gif, webp, pdf, else `application/octet-stream`), `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox; default-src 'none'`, `Cache-Control: private, no-store`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: same-origin`, no CORS, no ranges. `Content-Disposition: inline` for json, plain text and `text/calendar` (so a Tasks `.ics` feed works in a calendar client), `attachment; filename="<sanitised name>"` for everything else. Other methods are 405. A malformed token is the same 404 as an unknown one.
- Rate limit: 60 requests/minute per client address and 600/minute per route (one bridge process serves one app); a miss is charged a second unit (so 30 misses fill a client); a refused request is 429 with `Retry-After` and is not charged; the 429 does not depend on the token. Windows are in memory and slide per minute.
- Logging: one line per served link, `id`, status and bytes; misses are not logged; the token and the URL path never are.
- Tool: `everything-bridge links list -db FILE -app APP [-all]` and `links revoke -db FILE -app APP -id ID`; ids, owner names, paths, expiry, hits; never tokens or content.
- Shim: `getReadURL` accepts seconds or `30m`/`12h`/`7d`/`2w`/`1y` strings and returns the URL string; errors surface as `{code}` (`path_not_found`, `invalid_argument`, `read_link_limit`).

## Edge client address (verified from the generated config)
- Local and overlay names: app handles (`renderPathHandles`) and host routes use a plain `reverse_proxy` with no `X-Forwarded-For` line, and the edge never sets `trusted_proxies`, so Caddy 2.11 replaces any client-sent `X-Forwarded-*` with the address of the connection it saw.
- Tunnel entry (loopback-only listener, ADR-037): `header_up X-Forwarded-For {http.request.header.Cf-Connecting-Ip}`, i.e. what Cloudflare saw.
- The bridge believes `X-Forwarded-For` only when the TCP peer is in `-trusted-proxies` (default: loopback and private ranges, i.e. the edge over the private Docker network; apps publish no port). It takes the rightmost entry; if that is not an address it uses the peer. An untrusted peer's header is ignored. `none` trusts no peer; a custom CIDR list is accepted. IPv6 clients are grouped by /64.
- `internal/docker/pathroutes_test.go` fails if the generated config ever sets `trusted_proxies`, copies a client `X-Forwarded-For`, or the tunnel entry stops setting it.

## Tests
`internal/everything/readlinks_test.go`: hashed at rest, current content, TTL bounds and cap, expiry, revoke and wrong-app revoke, cross-person and cross-app mint, folder and `~shared` refusal, revocation on delete/rename/tree delete (sibling prefix kept, overwrite keeps, other person's delete harmless), recipient delete through a folder share, purge (owner, other person, other app, purged owner cannot mint), limits per path and per owner, route headers and dispositions, HEAD and 405, byte-identical 404s for nine failure kinds, no log of a miss or token, per-client and per-route limits with sliding window and double-cost misses, rate limiting on a spoofed header from an untrusted peer and from behind the edge, `clientAddr` table, CSRF/origin on mint, route registered under the base only. `cmd/everything-bridge/tools_test.go`: `links`. `internal/docker/pathroutes_test.go`: edge never forwards a client address. Gate bridge mode: a real-bridge test that mints from the shim, fetches anonymously, sees the update, and sees 404 after delete and re-create.

## Unproven
No live Caddy was run to confirm the header replacement (it follows from Caddy's documented default and the generated config); no live OIDC two-person run; no browser opened a read link. The public name, `read_links_not_exposed`, the edge route and the viewer are S432/S433; the Tasks and Notes UI stay as they were.
