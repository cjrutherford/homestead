# S430: Everything events

ADR-058 section 6. Depends on S425-S429. Bridge and shim only; no daemon, API, CLI or dashboard change, so no PARITY change. Tasks UI stays hidden (S437).

## Scope
`events.onLocal(subject, cb, {onError})` (alias `events.on`) returning `{off()}`; share notices; key-change events on the person's own prefix and on shared handles; `gap`.

## Design as built
- `internal/everything/events.go`. Stream: `GET <base>/_homestead/events?client=<id>` (Server-Sent Events, session cookie, no state change). Any `Origin` sent must be trusted and `Sec-Fetch-Site`, if sent, must be `same-origin` (a same-origin GET carries no Origin). Subscribe and unsubscribe are the POST data operations `events.subscribe` / `events.unsubscribe` (fields `client`, `topic`), so Origin, Sec-Fetch-Site, content type and CSRF apply. `client` (16-64 chars of `A-Za-z0-9_-`) is also sent with kv writes; a bad one is a 400.
- Switch: events need the `-sharing` switch (`events_disabled`, 403, when off).
- Subjects: `notif:app-user`; `kv:app-<app>:<prefix>*` (own app only, any prefix of the caller's own keys); `kv:<handle>:*` (needs an active grant and a session under 24 hours; else `kv_handle_not_found` 404 / 401). Everything else is `bridge_unsupported` (400): other apps, fs, unknown. `events_not_connected` (409) when the stream is not open for that person and client id, so guessing another person's client id reaches nothing.
- Frames: `event: ready` on connect; `event: msg` with `{subject, event}`; `event: gap`; `: ping` comments. Events: `{type:'kv.share.received'|'kv.share.revoked', handle}` and `{type:'fs.share.received'|'fs.share.revoked'}` for the recipient only; `{op:'set'|'del', key, self, viaWorker:false}` for keys (relative to the grant prefix on handle subjects). Values are never sent. `self` is true only for the writer's own client id on its own stream.
- Publishers: own writes (put, delete, putbatch) after a 200; writes through a handle (published in the owner's scope, so the owner's own-prefix subscribers hear a recipient's write); `kv.share` / `kv.unshare` / `fs.share` / `fs.unshare`.
- Re-checks: every delivery re-validates the session, that the person is not purged, and (handle events) the grant; a failed grant drops the subscription and sends `gap`. `kv.unshare` drops the handle's subscriptions at once and sends the recipient `kv.share.revoked` and `gap`. The heartbeat re-checks everything, so a purge or a revoke by the other-process tools ends the stream or drops the handle within 25 s. A recipient stream with handles ends when its session passes 24 hours.
- Limits: 5 streams per person (6th: 429 `events_stream_limit`; the same client id reconnecting replaces its old stream), 50 subscriptions per stream (`events_subscription_limit`), 256-event queue (overflow collapses to one `gap`), heartbeat 25 s, stream closed after 1 h, and after 2 minutes with no subscription. Per-write deadlines (10 s) let a stream outlive the server's read and write timeouts.
- Shim: one `EventSource` per page, opened on the first `onLocal`; waits for `ready` before subscribing; one server subscription per distinct subject with local fan-out; callbacks get `{event}`; after a reconnect the shim re-subscribes and calls every callback with `{event:{op:'gap'}}`; when the bridge refuses the stream (EventSource closed) every `onError` fires and the caller polls. Without `EventSource` (node) `onLocal` rejects `bridge_unsupported`. Last `off()` closes the stream.
- Service workers: every `*-sw` template and `files/sudoku-sw.js` already returns without `respondWith` for `./_homestead/`, so the stream is never cached (checked by reading all of them).
- Edge: generated Everything routes use a plain `reverse_proxy` (internal/docker/routes.go); there is no `encode`. Caddy's reverse_proxy flushes `text/event-stream` responses immediately (its documented behaviour), the bridge also sends `Cache-Control: no-store, no-transform` and `X-Accel-Buffering: no`, and the heartbeat is under Cloudflare's 100 s idle limit. Not verified against a live Caddy here. If an edge buffers, add `flush_interval -1` to the `reverse_proxy` of the Everything route (and its tunnel entry) and do not compress `text/event-stream`; Tasks polls anyway.

## Tests
`internal/everything/events_test.go` (real HTTP server): own-prefix and `self`, no values on the wire, handle events with relative keys, recipient writes seen by the owner, share and revoke notices (kv and fs), revoke drops the handle, cross-person and cross-app denial, subject scoping, limits (streams, subscriptions, replace), queue overflow and gap on the wire, heartbeat and headers, endings (session end, purge, max age, idle, revoke elsewhere, stale session), Origin / Sec-Fetch-Site / method / CSRF refusals, sharing off, stale session, route under a base path, survival of server timeouts. Gate bridge mode 10/10 (stubbed `EventSource` test of the shim). Projects browser check. Python source test updated.

## Unproven
No live OIDC two-person run, no live Caddy/Cloudflare streaming check, no real browser `EventSource` run against the bridge (the Projects browser check does not subscribe). Real Tasks code does not use events yet (S437).
