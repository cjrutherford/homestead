# S471 - Move plan from a subdomain to a subpath

## Goal and dependencies
Fourth slice of ADR-061. Depends on S469 (`publish` field) and S470 (shared-origin hardening). An installed app whose package is `serve: path` but is still published at its own name `<app>.<zone>` gets one reviewed, digest-bound move to `https://<dashboard public name>/apps/<app>/`. The old name is removed cleanly: no redirect. No app moves in this slice (S472 to S477 move one each); the code path is exercised by tests and a test-only fixture.

## What changed
- **Move plan (API, CLI, dashboard).** The existing move (`GET /catalog/{name}/move`, `POST .../move/plan`, `POST .../move/apply`) is extended, so there is no new route or command. Before, an app holding a public name was refused ("take its public name off first"). Now, when the app has exactly one public name, the dashboard has a public name and a tunnel is recorded, the plan carries `public_from`, `public_to`, `removes` and `stops`, and the digest covers the old name and tunnel. The preview says plainly that **old bookmarks and links on the removed name stop working and nothing redirects**, that clients with the saved server address must be changed by hand, that no DNS record is needed for the new address, and what is removed (the proxied CNAME, the connector ingress entry, the public edge route). `homesteadctl apps move status|plan` print the same fields; the dashboard move card shows them.
- **Order (publish first, remove last).** App settings (`app_url` and the like through the move environment, including the `{{app_url}}` token), host allow-list (gains the dashboard's public name, loses the old name), then the edge (path route published on the dashboard's name, the route's own tunnel name dropped), sign-in re-plan (issuer and redirect URIs, S400), the craft files link where it applies, then `verify-path`, `connector`, `delete-dns` (only while the CNAME still points at the tunnel) and `restore-dns`. A failure stops the run and the connector entry and CNAME stay, so nothing is half-removed before the new address answers. The audit entry `app.move` records the public address change.
- **Refusals.** A `publish: host` package is refused with its reason (`PublicFormReason`); Uptime Kuma and any `never` package are refused a publish and a move; a `never` package holding a public name is not moved with it; an app with several public names, Authentik, or a dashboard with no public name is refused with the reason.
- **`publish` is read.** `never_publish` (S451) is removed from the manifest schema and from `uptime-kuma.yaml`. `Manifest.PublicRefusal()` and Doctor's `never-publish` check read `publish: never`; the install wizard reads `Publish === 'never'`. The refusal text is generic (a craft app is `never` too). The status field `never_publish` of the public API is unchanged.
- **Cookie warning (S470 deferred item).** New manifest fact `cookie_path_root` (set only after an app was checked) adds a Path=/ cookie warning to the move plan and the path-publish plan. No manifest sets it yet; each package slice (S472 to S477) sets it when it checks the app.
- **Doctor.** New `subpath-publish` check (Tunnel group): warns "move available" for an installed `publish: path` app still on a public name of its own, with the move command as the fix; warns for an app published at its path when the dashboard has no public name. The `never-publish` check also fails a `never` app published at a path.

## Not covered
See `docs/DEFERRED.md` (S471): a half-done move leaves an orphan connector entry and CNAME; "public name with no matching approved plan" Doctor check; verifying the new address with a live request.
